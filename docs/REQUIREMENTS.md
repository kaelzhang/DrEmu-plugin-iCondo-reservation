# 需求

需求原文在 `prompts/requirement.md`（git 忽略，Kael 本地维护），用户原话的台账在 `.omnipowers/requirements.md`。本文件记录当前的最终理解。

## 目标

在 DrEmu 模拟的 Android 设备（竖屏 720 × 1280）上驱动 iCondo（`com.icondo`），预订小区的**网球场**。iCondo 的门禁（F1）和篮球场不在本插件范围内。

## 面板

一次只设一个任务：

- **周**：本周 / 下周。**星期**：周一…周日；本周已经过去的日子不可选（今天可选）。
- **时段**：08:00 … 21:00 开始的 14 个一小时时段一字排开，点选 / 取消；可选一个，或两个相邻的——选了一个后，不相邻的时段禁用。
- **预订**：日期已开放就立即预订；还没开放就进入等待，保活，在开放那天 00:00 立即抢订。成功后不取消。
- **测试**：预订一个现在就开放的日期，成功后自动取消。用来验证整条路径。
- 进行中的任务可以停止。任务的阶段、开放倒计时、结果和失败原因显示在面板上，并写入预订日志。

## 预订规则

- 从今天起自然一周内可订：今天周四，最远到下周三。所以日期 D 在 D 前 6 天的 00:00（Mac 本地时间，即小区时间）开放。
- 要的时段只要有一个不可用，整个任务失败（两个时段只剩一个可用也算失败）。
- 只有看到预订成功页（`calendar`）才算成功。

## 术语与画面

| 画面 | 怎么认出 | 怎么离开 |
| --- | --- | --- |
| 首页 | `home` 和 `facility` 都匹配（facility 图标和设施页的 book 标签很像，单看它会认错） | 点 `facility` |
| 设施页 | `book-tab` 匹配（on 或 off）；`active-tab` on 表示在 active 标签 | 本插件的终点 |
| 预订页 | 右上角日历图标（`tennis-page`，从 `tennis-court.png` 裁出） | `back` |
| 条款页 | `agree` | 点 `agree` → 确认页；`back` |
| 确认页 | `confirm` | 点 `confirm` → 成功页；`back` |
| 成功页 | `calendar` | `back` |
| 取消确认（sheet） | 往上滑能扫到 `cancel-yes` | 点 yes；或系统返回 |

导航（Kael：「大部分的界面都会包含 back 按钮」）：优先点页面里的 `back`；只有在已知的内层页面上、又找不到 `back` 时才点 `system-back`。在首页或认不出的画面上**绝不**点 `system-back`（Kael：「你不要点击 system-back 导致关闭 app 了」），直接停止并报 `unknown_screen`。每一步都检查前台仍是 iCondo。

流程细节见 `docs/FLOW.md`。

## 不处理

- 配额（「2x quota left」）用完时的界面：Kael 说先不管。它会表现为某一步等不到（例如 `next_not_lit`），任务失败并写明原因。
