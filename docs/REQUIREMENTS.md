# 需求

这个插件要做什么、规则是什么、Kael 做过哪些裁定。原文在 `prompts/requirement.md`（git 忽略，只在 Kael 本地）；本文件把原文和之后对话里的补充都写全了，不读原文也能工作。Kael 的原话逐条在 `.omnipowers/requirements.md`。

## 背景

iCondo（Android 包名 `com.icondo`）是住宅小区用的 App，有两个作用：

- F1：访客在门禁输入主人的手机号和房号，会打电话到 App，主人在 App 里开门。**不在本插件范围内。**
- F2：主人在 App 里预订球场。原文讨论网球场和篮球场；**本插件只做网球场**（Kael 确认，2026-10-01）。

设备是 DrEmu 模拟的 Android，竖屏 720 × 1280（Kael 确认）。设备状态栏显示的是 UTC（截图里 4:51 对应新加坡 12:51）；插件按 Mac 本地时间（小区时间，UTC+8）计算一切日期和 00:00。

## 面板

一次只设一个网球场任务：

- 下拉：本周 / 下周。
- 下拉：周几。按今天判断哪些可选——过去的日子不可选（例如不能订昨天）；今天可选。
- 时段：08:00 起到 21:00 起的 14 个一小时时段一字排开，点选 / 取消；可选一个，或两个相邻的。选了一个以后，不相邻的时段禁用。
- 「预订」：如果现在就能订，立即去订；如果还没到可订的日子，就开始规划、保活，在可订那天的 00:00 立即抢。成功后不取消。
- 「测试」：去预订，成功后自动取消（Kael：「这个测试就会预订，预订成功，然后自动取消」）。只用于现在就能订的日期。
- 任务失败要在面板上说明情况和原因，并记录预订日志。

## 预订规则

- 只能预订从今天起自然一周内：今天周四，最远到下周三；所以周五 00:00 起可以订下周四。即日期 D 在 D 前 6 天的 00:00 开放。
- 面板要的时段只要有一个不可用，任务就失败——两个时段只剩一个可用也算失败（Kael：「失败」）。
- 只有到达预订成功页、看到 `calendar`，才算完成。
- 配额（页面上的「2x quota left」）：Kael 说先不管。配额用完会表现为某一步等不到（例如 `next_not_lit`），任务失败并写明原因。

## 抢订

- 接到未开放的任务后，先进入设施页、上滑到 tennis court 可点的位置，准备在 00:00 立即进入。
- 为防设备休眠，每 30 秒点一次 `facility-keep-alive`。
- 先实测「进入预订页 / 返回」要多久，按这个耗时提前点击（Kael 的例子：进入要 1 秒，就在 23:59:59.500 左右点 tennis court），进去后立即看目标时段是否可用，可用就立即预订。可能失败：小区里别人也在抢。

## 画面与导航

画面怎么认、怎么离开（素材细节见 `docs/ASSETS.md`）：

| 画面 | 怎么认出 | 怎么离开 |
| --- | --- | --- |
| 首页 | `home` 和 `facility` 都匹配（能匹配 `facility` 说明在首页，但设施页的 book 标签和它很像，所以还要 `home`） | 点 `facility` |
| 设施页 | `book-tab` 匹配（on 或 off）；`active-tab` on 表示在 active 标签 | 本插件的大本营；book 标签必须是 on，不是就点（幂等） |
| 预订页 | 右上角日历图标（`tennis-page`） | `back` |
| 条款页 | `agree` | 点 `agree` → 确认页 |
| 确认页 | `confirm` | 点 `confirm` → 成功页 |
| 成功页 | `calendar` | `back` |
| 取消确认（一个 sheet） | 往上滑直到扫到 `cancel-yes` | 点 yes |

- 大部分页面都有 `back` 按钮，用它和上表在页面之间导航（Kael）。
- `system-back`（系统导航的返回）也可以用（Kael），但**绝不能因此关掉 App**（Kael：「你不要点击 system-back 导致关闭 app 了」）：只在已知的内层页面上、找不到 `back` 时用；首页或认不出的画面上不点，直接停止并报 `unknown_screen`。
- **点击之后不能立即判断，要 waitFor + 超时**（Kael：「你不可以在 tap Region 之后，就立即做判断，你需要 waitFor」「因为在 app 里面，很多下一个页面是需要推进来的」「不是两次读取，而是默认情况下，你需要 waitFor + timeout」）。
- 每一步都确认前台仍是 iCondo。

## 预订页

- 上方是星期，**按星期几定位，不看日期数字**。星期区域固定两行、位置固定，每行周一到周日；时间区域也固定，每个圆角矩形对应 08:00–22:00 中的一小时。所以不做文字识别，按固定位置判断状态和点击。
- 日期格三种状态：不可预订（浅灰背景、浅灰数字，只看背景色即可）；当前选中（青绿背景、白色数字）；可选（略深的灰背景、黑色数字）。
- 时段格三种状态：不可用、可用未选、已选中（`tennis-court-next.png` 里有全部三种）。
- 按面板选择点日期、点时段；next 亮起后点 next。

## 预订后续

next → 出现 `agree` 就直接点 → 进入确认页，waitFor `confirm` 后点 → 进入成功页，waitFor `calendar` 成功才标记任务完成。

## 测试与取消

在设施页幂等地点 `active-tab` 进入 active 页 → 纵向扫描找到 `cancel` 并点击 → 弹出 sheet → 上滑直到出现 `cancel-yes`（纵向扫描）→ 点击 → 回到 active 页（active 标签 on）即取消成功。插件只取消日期和时间都对得上刚订那条的卡片（用数字识别读卡片），对不上就不取消并报 `cancel_not_found`。
